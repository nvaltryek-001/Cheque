# Dataset test results

Date: 2026-11-01 · branch `chequeverify-v2` · measured on a 2-CPU sandbox with Tesseract 5.3 and the bundled E-13B MICR templates.

This report contains **no cheque images, account numbers, payee names, amounts or signature images**. Cheques are
described by bank and by counts only. The images, the labels and the full per-cheque score table stay outside
the repository (they are excluded by `.gitignore`, `.dockerignore` and the pre-push audit).

## 1. Source
The project dataset was supplied with the project: one folder of cheque images for OCR and one folder of signature
images with two manifests. Its real-world origin, and whether the people in it consented to this use, are not
documented anywhere in the repository. Nothing in it has been invented or generated by this project; the
"forged" signatures were generated by scripts that came with the dataset (see section 6).

## 2. File counts (read-only audit: `python backend/manage.py audit`)
| | OCR cheques | Signatures |
|---|---|---|
| Images | 120 (PNG, 0.48 to 1.07 megapixels, median 0.49) | 360 |
| Content | train 80, validation 20, test 20; four banks (Axis, Canara, ICICI, Syndicate), 5 test cheques per bank | 120 "genuine" (one per signer) + 240 "forged" (script-made edits of the genuine ones) |
| Other files | none | 2 manifests (CSV), 2 generator scripts |
| Missing images | 0 | 0 |
| Corrupted images | 0 | 0 |
| Exact duplicates | 0 | 0 duplicate file names; 0 alterations whose target is missing, in another split or at another bank |

Every image is far below the 12-megapixel upload limit of the Docker image.

## 3. Splits
* OCR: the folders `train`, `vaildate` (sic, as delivered) and `test`. The MICR templates are learned from `train` only;
  `validation` and `test` are not used for learning them.
* Signatures: split by signer, so one signer's images are never in two splits (details and thresholds in
  `MODEL_EVALUATION.md`).

## 4. Processing run of 2026-11-01 (the real upload path)
`python3 -I scripts/time_uploads.py backend <path to the OCR test split>` uploads every image through
`POST /api/cheques` (login, rate limit, image slot, decoding, OCR, field extraction, database write), in process.

| Measure | Result |
|---|---|
| Test cheques uploaded | 20 of 20 accepted (HTTP 201), no errors |
| First request (loads the models) | 3.98 s |
| The other 19, one at a time | median 4.18 s, 90th percentile 4.52 s, slowest 4.84 s |
| By bank (median) | Axis 3.6 s, Canara 4.0 s, ICICI 4.2 s, Syndicate 4.5 s |
| Eight uploads at the same moment | all HTTP 201, all finished after 18.5 s; each request waited 11 s (median), 17 s (90th percentile) because two images are processed at a time |
| Throughput | about 0.25 cheques per second on 2 CPUs |

**The time is OCR work, not upload time.** A hosted Render Starter instance has less CPU than this sandbox, so
expect each cheque to take longer there, not shorter. A larger plan (more CPU) is the direct way to make results appear
sooner; so is a smaller OCR workload (fewer re-reads per field), which would cost accuracy.

## 5. OCR results (`reports/final/ocr_evaluation_test.json`, `DATASET_VALIDATION_REPORT.md`, `MASTER_PROJECT_NOTES.md` section 7)
Fill rate on the 20 test cheques (share of cheques where the field was read at all):

| Bank | Branch | IFSC | Cheque no. | MICR code | Account no. | Date | Payee | Amount (figures) | Amount (words) |
|---|---|---|---|---|---|---|---|---|---|
| 100 % | 85 % | 100 % | 100 % | 100 % | 90 % | 95 % | 100 % | 100 % | 100 % |

Accuracy against the labels: **196 of 200 fields (98 %)**, 0 wrong values marked "ok"; the 4 remaining wrong fields
are all flagged for review. Cheque number, MICR code and bank name were 20/20 each. Cross-checks: amount in words
agrees with the figures on 17 of 20 (85 %); the date is valid on 19 of 20; the account number is found in the
enrolled-signer registry for 18 of 20.

**Read these numbers with their limits:**
* The labels were transcribed from the images by the AI assistant, not by a person. One was already found wrong.
  They need human verification before any accuracy is quoted outside this project.
* The test split is **not blind**: the extraction rules were tuned while looking at it. Accuracy on cheques nobody has
  looked at will be lower, by an amount that has not been measured.
* Four banks, clean flat scans around 0.5 megapixels. Phone photos, other banks and poor scans have not been tested.

## 6. Signature results (counts only; no claim about real forgeries)
| Measure | Result |
|---|---|
| Signature of another signer accepted as a match | 0 of 380 test pairs; 0 of 14,280 pairs over all 120 signers |
| Other-signer signature, test | accepted 0 of 60 |
| Script-made edit of the specimen, submitted unchanged (this is **not** a forgery by another person) | accepted 2 of 40, rejected 21 of 40, sent to review 17 of 40 |
| Genuine acceptance rate / false rejection rate | **not measurable**: the only "genuine" image per signer is cropped from that signer's own cheque |
| Skilled-forgery acceptance / rejection | **not measurable**: the dataset contains no forgery made by another person |

About 80 of the 120 "genuine" signatures look like names typed in a script font rather than handwriting (a visual
impression, not verified). **These results do not show that the system detects real forgeries.** The enrollment and
evaluation workflow for collecting the data that would (`docs/SIGNATURE_ENROLLMENT.md`, `manage.py eval-signatures`)
is built and tested with synthetic data; it has not been run on real consented samples.

## 7. Failed and missing cases
* 4 of 200 OCR fields wrong (flagged for review). Details are in the private score table, not here.
* Not read at all: branch on 3 cheques, account number on 2, date on 1.
* Amount in words disagrees with the figures on 3 cheques (the pipeline cross-checks the two and reports a disagreement).

## 8. Dataset limitations
Labels not human-verified; test split not blind; four banks; no independent genuine signature per signer; no real
forgeries; signatures that look typed; provenance and consent undocumented; no phone photographs; 120 images is
small. The hosted copy does not contain the dataset (privacy): after sign-in, use **Batch upload** on the Cheques
page to load cheques into it.

## 9. Reproducible commands
```bash
python backend/manage.py audit                         # counts, missing/corrupt/duplicate files -> reports/final/*_AUDIT.json
python backend/manage.py train-micr                    # learn the MICR templates from the train split
python backend/manage.py eval-ocr --split test         # OCR field evaluation on a split
python backend/manage.py score-ocr --images DIR --labels CSV --masked-report OUT.md   # score against labels kept outside git
python backend/manage.py eval-signatures --dataset     # what the signature data can and cannot measure
python3 -I scripts/time_uploads.py backend DIR_WITH_ONE_FOLDER_PER_BANK               # the timing run of section 4
```
